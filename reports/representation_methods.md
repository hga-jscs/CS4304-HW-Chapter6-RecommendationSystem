# 通用用户表征的方法依据与实验状态

截至 2026-11-18，本项目继续在固定官方下游模型下改进表征。文献提供候选方向，不提供本项目必然达到 `0.750 / 0.815 / 0.815` 的保证。本文件记录方法来源与实施范围，不是达标后的课程正式报告。

## 历史排行榜与本地结果的区别

RecSys Challenge 2025 冠军 rec2 的公开最终成绩为 churn **0.7375**、category **0.8179**、SKU **0.8224**。获奖身份见[主办方结果](https://recsys.synerise.com/results/winners)，具体分数可交叉核对[亚军论文 Table 2](https://arxiv.org/html/2508.07748v1)和[第四名论文 Table 1](https://arxiv.org/html/2508.06970v1)。冠军的综合第一来自六项任务的排名汇总，并非每项任务均第一。

不能将论文内部验证、历史线上成绩和本项目成绩混成一个排行榜。例如亚军在自己本地划分上的组合 churn 为 0.8212，而其最终线上为 0.7376，论文分别列于 Table 3 与 Table 2。本项目使用当前下载的预处理数据及固定官方提交做本地评测；是否同一历史榜单环境不能仅由指标名称推断。我们的 churn 目标高于上述冠军分数，说明目标较高，不代表 0.7375 是不可突破的上限，也不应据此下调用户目标。

## 三个可检验的文献方向

| 方向 | 已核实的原方法 | 本项目适配与当前状态 |
| --- | --- | --- |
| 分块归一化与互补向量拼接 | 亚军对学习向量分别做 L2，对统计特征采用 uniform QuantileTransformer，部分向量先 PCA 后拼接。依据：[原论文 §3.3](https://arxiv.org/html/2508.07748v1)、[作者最佳配置](https://github.com/antklen/recsys_challenge_2025/blob/main/scripts/config/best_solution.yaml)。 | 普通列标准化、分组缩放和向量拼接已经实测；**分位数缩放仍是文献建议，尚未执行**。它可复用现有原始统计块，仅从历史输入拟合变换；不能把已有分组缩放称为已复现 QuantileTransformer。 |
| 轻量序列重构 | 亚军的 day/event 自编码器重构日期与事件类型，作者配置为 hidden 128、两层 GRU、最长 128 步、batch 256。依据：[原论文 §3.1](https://arxiv.org/html/2508.07748v1)、[配置](https://github.com/antklen/recsys_challenge_2025/blob/main/gru_autoencoder/config/gru_ae_day_event.yaml)、[训练入口](https://github.com/antklen/recsys_challenge_2025/blob/main/gru_autoencoder/gru_ae_day_event_embeddings.py)。 | 可用现有 64 步缓存先研究 128 维互补块，但这是缩小改编，**尚未实现或训练**。当前预训练 GRU 学习伪未来标签，不是自编码器，不能沿用论文的实验结论。 |
| 历史与后续行为的对比学习 | 冠军以同一用户的过去、后续行为构成正对，并预测后续是否有事件；最终只用历史侧编码器产生表征。依据：[作者技术说明](https://blog.recruit.co.jp/data/articles/recsys-challenge-2025/)、[作者配置](https://github.com/yukia18/recsys-challenge-2025-1st-place/blob/main/cl_transformer/scripts/conf/create_embeddings.yaml)。 | 可在历史 input 内利用 A/B/full 切窗，学习小型共享表征；**尚未实现或训练**。目前的 immediate/delayed BCE 预测头不等于对比学习。冠军论文 DOI 为 [10.1145/3758126.3758137](https://doi.org/10.1145/3758126.3758137)，本次正文访问受限，技术细节据作者本人说明与源码核对，没有声称已读取该论文全文。 |

这些适配均要求表征及伪监督只来自历史 `input/`；官方目标期事件和类别清单不参与新表征或词表选择。作者完整工程不可直接等同于本机可运行方案：冠军对比学习的[环境说明](https://github.com/yukia18/recsys-challenge-2025-1st-place/blob/main/cl_transformer/README.md)为 A100 40GB、83GB RAM。维数预算也需要单独核算：当前 1797 维若追加两个 128 维块，会达到 2053，超过官方 2048 维上限。下面实际推进的 77 维和 128 维组合为 2002 维。

## 购买节律与商品共现的完整对照

下面两项已完成全量构建及固定官方三任务评测，其余文献方向仍保留为建议。正式结果列于上表，不能将文献方法的分数当成本项目分数。

1. **77 维活跃节律与历史树模型块，先追加到 1797 维得到 1874 维。** 五类事件各提供 15 维日级窗口和间隔特征，共 75 维，再加入两个历史滚动训练的复购分数。窗口为 7/14/28/56/112 日；两项监督分别预测未来第 1–14 日和第 15–28 日，均在历史 input 内构造，验证使用时间留出与 28 日间隔。最近/上次活动间隔按不同日期计算，不把同日商品件数当作复购次数。[第四名原论文 Appendix A](https://arxiv.org/html/2508.06970v1)提供多时间尺度和独立购买日特征依据，但论文使用的 7/14/28/60 日窗口及 DCN 与这里的滚动梯度提升树不同；两项输出是复购 log-odds，并非校准 churn 概率。
2. **128 维商品共现块，再追加到 1874 维得到 2002 维。** 仅用购买与加购学习共享商品因子，再分别生成 64 维购买、64 维加购用户向量；实现采用历史频次至少 3 的 SKU，而非固定 Top-4096 截断。矩阵进行 `log1p`、IDF 与行归一化，使用稀疏谱投影，避免显式构造稠密商品共现矩阵。[第四名原论文 §2.2](https://arxiv.org/html/2508.06970v1)支持分别利用购买和加购关系的动机，但其方法是带负采样训练、可学习用户/商品/关系参数的 TwHIN；本项目的谱分解不是 TwHIN 复现，不能继承论文分数。

77 维块已经完成百万用户构建，耗时 95.645 秒；历史留出窗口中，近、远两窗复购 AUC 分别为 0.76548、0.74174。这只是内部检查，不是官方 churn 成绩。追加该块后正式分数变化为 **+0.0008/+0.0001/−0.0003**；再加商品共现块为 **+0.0001/+0.0001/+0.0003**。该方案的建模人群是各锚点前 112 日内的买家，不能写成官方全部历史买家；最早锚点也未必有完整 112 日的可观察历史。这些是可能影响迁移的限制，不是已证实的失分原因。

正式对照顺序为 **1797 → 1874 → 2002**，用于分别比较新增活跃块、再新增商品块的变化；没有安排单独的 1925 维商品组合评分。两次候选均已完成三项固定评测，最佳 epoch 索引分别为 2/2/2 和 1/2/2，官方评测总计分别为 3966.499/4067.043 秒。不得拼接不同实验的单项最好分；这个顺序也不能单独估计商品块在不含活跃块时的效果。仅有单种子与单一公开划分，0.0001 级差值不能视为已证明的稳定收益。

SKU 的四位成绩也掩盖了极小差异：2002 维的未舍入分数为 **0.8057305694**，1797 维为 **0.8057394981**，实际变化约 **−0.00000893**，两者在官方输出中均为 0.8057。因此不能把 2002 维写成 SKU 严格提升。

## 个人购买节律的信息限制：事后诊断

在 510,971 名历史买家中，验证期有 44,022 人复购。仅在一个不同日期购买的 393,692 人占历史买家 **77.05%**；其中 22,465 人复购，组内复购率 **5.71%**，仍占全部历史买家复购人数的 **51.03%**。其余 117,279 名多购买日用户中有 21,557 人复购，组内复购率 **18.38%**。这说明多数用户缺少可直接估计个人重复购买间隔的历史，但单日买家仍包含超过一半的验证期复购者，不能将他们视为必然流失。

只把“距上次购买的日数”作为风险分数、不训练任何模型，得到整体 churn AUROC **0.64245**，单购买日组为 **0.57522**。这支持个人购买节律信息有限的解释，但不证明它是本轮失分的原因，也不是可学习模型的性能上限或正式神经模型的分组成绩。该诊断在实验完成后读取验证期标签，仅用于解释；未用于表征构建、词表选择或调参，不是新增上线模型。原始诊断与来源哈希保存在本地 `准备资料/复购难度诊断.json`，正式实验仍以 [purchase_results.json](../extension/purchase_results.json) 为准。
