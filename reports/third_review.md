# 第三轮意见核验与诊断

本轮目标仍为 Synerise 三项官方分数至少 `0.750 / 0.815 / 0.815`；KKBox 已达到 `0.71053 / 0.71070`。核验基于提交 `25f3162` 的源码、已有表征与预训练缓存、原官方 Neptune 离线浮点记录，以及只读的历史行为统计。以下诊断不是新模型成绩。

两份意见提供了值得试验的特征方向，但“5 个已经证实的 P0 致命 Bug”这一判断不成立。实现缺失、建模选择和未经验证的因果解释需要分别处理。

## 意见逐项判断

| 意见 | 核验与处理依据 |
| --- | --- |
| 买与加购混合是致命 Bug | 544 维的精确 Top-K 块确实混加买/加购，这是信息压缩的设计选择，并非写入错误；原 673 维和预训练输入已有分开的买、加购、移除块。新候选拆分行为，增加短期 `cart−remove−buy` 余额代理。事件次数没有数量和订单关联，不能称为真实未支付购物车状态。 |
| 全列标准化把尾部噪声放大 100 倍 | 标准化确实改变因子相对尺度；实际图因子列标准差为 0.0360–0.3274，尾部 64 列不是意见给出的约 0.01。无法仅凭缩放系数判断哪些方向是噪声。分块缩放作为可对照的候选，不能预先认定必涨分或全列标准化必错。 |
| churn 被 200 个倾向头淹没 | 代码将 category 与 SKU 分别求均值，然后以三个任务损失相加，并未直接累加 200 个类别损失。churn 只对伪输入买家计算。实际 checkpoint 诊断也不支持“梯度不足 5%”。改变正例权重和任务权重仍可试验，但属于优化目标的改变。 |
| 没有序列模型、没有 URL 特征、没有买家掩码 | 不符合当前实现：已有 GRU、URL 哈希统计/序列 item 编码及买家 mask。确实未将 PQ 与图因子输入预训练主干；search 事件保留事件/时间信息，但序列没有 query 内容。可以改进内容覆盖，不能把已有内容说成完全不存在。 |
| 一个伪时间窗必然泄漏或丢失最近 14 日信息 | 伪输入与伪目标分离是构造监督的必要步骤；最终提取已使用完整历史。单个锚点可能造成迁移困难，多窗口可检验该假设，但不保证消除分布差异。不同窗口必须共享用户划分、词表及因子坐标，不能将各自重拟合的 SVD 轴直接当作同一列。 |
| 单次买家的间隔设零破坏风险单调性 | 一个事件无法估计个人购买周期，旧实现用零表达缺失，同时已有 count、recency、has_history。建议的 `max(recency,14)` 会让长期未购者的比值趋近 1；中位数填补也不保证风险单调。新候选显式区分有无重复购买日，并保留真实 recency。 |
| IDF、多关系图必然提升 Novelty | IDF 和事件权重是合理候选，但其对最终分数需实测；当前 SKU Novelty 已约 0.992。第二份意见的负权移除边不能直接接入现有 `log1p` 图流程，否则可能出现无效数值；负向意图宜与非负图统计分开。 |
| 名称与搜索 PQ 池化能直接实现语义对齐 | 旧版两者分别拟合共现 SVD，坐标不天然对齐，也没有原始 PQ 码本。可以分别投影或加入来源标识进行学习，不能把两个独立 32 维向量直接称为共享语义坐标。 |
| 64 步/双向 GRU 可在 3–5 分钟保证达标 | 序列覆盖不足有实测依据，见下文。结构和耗时仍是待验证方案，增加层数、长度及双向性不等于保证收益。 |

## 官方指标分解：主要缺口并非统一的“新颖度天花板”

按每个实验原官方加权分数最高的 epoch 读取精确浮点值，下面显示六位小数。分数为 `0.8×AUROC + 0.1×Diversity + 0.1×Novelty`，不是单独 AUROC；不同表征的单项最好分不拼成一套成绩。

| 表征与任务 | AUROC | Diversity | Novelty | 官方分数 |
| --- | ---: | ---: | ---: | ---: |
| 673 维 category | 0.769449 | 0.905630 | 0.899781 | 0.7961 |
| 544 维 category | 0.782102 | 0.900868 | 0.896598 | 0.8054 |
| 1001 维 category | 0.782823 | 0.900855 | 0.889277 | 0.8053 |
| 673 维 SKU | 0.749707 | 0.891041 | 0.991873 | 0.7881 |
| 544 维 SKU | 0.761724 | 0.887566 | 0.991122 | 0.7972 |
| 1001 维 SKU | 0.762272 | 0.895006 | 0.991932 | 0.7985 |

1001 维的 category AUROC 比 544 维略升，但 Novelty 降低约 0.007321，抵消了 AUROC 增益，最终精确加权分数下降约 0.000156。对于 category，分数与判别力并不完全同向。

SKU 的 Novelty 已接近 1。固定其现有 AUROC，即使将 Diversity 与 Novelty 都提高到 1，分数也至多为 `0.8×0.7622724771+0.2=0.8098179817`，仍小于 0.815。只改置信度或新颖度不能单独使 SKU 达标，必须改善 AUROC。官方 Novelty 本身还使用 Top-10 预测概率的幅度，不能简单理解成只计算是否推荐热门商品。

另一个 SKU 迁移限制是类别覆盖：旧伪输入选择的 Top-100 SKU 与官方 100 个 SKU 仅重合 24 个，旧完整历史 Top-128 SKU 仅覆盖 35 个；category 相应为 96/99 个。伪任务 logits 因而不是直接对应官方 SKU 的预测。此比较仅用于诊断，不以官方目标清单反向选择表征词表；历史侧的近期变化、较广协同图和内容迁移仍需实测。

这不等于其余 SKU 没有历史信息：官方 100 个 SKU 全部在 input 的购买和加购中出现，在相关 100 万用户子集内也全部有这两类事件；没有仅见于 metadata 或从未见过的 SKU。旧图 manifest 未保存商品编号；仅按旧实现的购买/加购频数与并列排序重建 Top-4096 词表（未构图或生成表征）后，覆盖为 **88/100**。因此，24/100 只描述辅助输出头的直接类别覆盖，不能把主要差距归因为商品完全冷启动。

历史支持仍很不均衡。在相关用户中，100 个 SKU 的购买记录数最少 1、中位数 154、最多 1088；其中 7 个只有 1–9 条，33 个只有 10–99 条。加购记录最少 3、中位数 374、最多 4005；2 个只有 1–9 条，19 个只有 10–99 条。这些是事件数，并非独立买家数。稀疏支持、词表压缩与时间变化可作为后续解释的候选，当前诊断没有证明各因素的因果贡献；全历史出现过也不保证最近输入窗有足够信号。

## 损失与特征尺度的实际测量

旧伪窗口训练中，419,205 名训练买家有 394,708 个 churn 正例，正例率 94.1563%，正负平衡对应的 `pos_weight` 为 0.062064。非买家已被 mask 排除，改变成 `pos_weight=1` 不是修复人群错配。

以选中的旧 checkpoint，在固定种子抽取的 8,192 名伪验证用户上进行 CPU 推理和瓶颈梯度诊断，没有优化器更新：

| 任务 | 加权 BCE | 对共享瓶颈的梯度范数 |
| --- | ---: | ---: |
| churn | 0.070424 | 0.008027 |
| category | 0.068219 | 0.006378 |
| SKU | 0.012456 | 0.002467 |

churn 范数占三个范数之和约 47.6%，不支持意见中的不足 5%。这是 checkpoint 快照；各任务梯度可能相互抵消，因此不能将范数比例当成完整训练期间的梯度贡献分解，也不证明现有权重最优。新权重配置应同时检查各任务内部验证指标，不能直接比较定义不同的加权总 BCE。

图因子标准化前，前 64 列标准差中位数 0.04636，后 64 列为 0.05092；后者对应标准差缩放倍率 13.07–26.69、中位数 19.64。所谓“标准差放大”和“方差放大”还需区分：方差倍率是标准差倍率的平方。实际数值不能证明尾部全是噪声；应比较相同原始特征的列标准化与分块缩放。

新 544 维分组缩放产物已用只读 mmap、每次 2,048 行核验：统计块的均值与 scale 完全一致，但新路径先将标准化数值落到 `float32` 再转 `float16`，旧路径直接从 `float64` 转 `float16`。因此 352,000,000 个统计值中有 958 个存在双重舍入差异（约 0.000272%，82 列），最大绝对差 0.0078125；这组实验不能称统计列逐元素完全相同。名称、查询、图的原零向量行分别为 489,029、656,560、163,701，缩放后均保持全零。非零向量与原方向乘 2 的最大逐值差为 0.00048828125，处于 `float16` 量化范围；原始文件大小、修改时间与生成前记录一致。保留这一量化限制，不中断评测或覆盖已有产物。行 L2 保留各用户向量方向，并不严格保证整个矩阵的奇异值谱不变。

## 购买周期与序列覆盖

只读取 `input/product_buy.parquet`，并限制在相关的 100 万用户中：

- 1,304,215 条购买记录对应 797,274 个不同的“用户、时间戳”组合，38.87% 的记录是同一组合下的额外商品；按 UTC 日期合并则有 728,552 个不同的“用户、购买日”组合。
- 510,971 名买家中，只有一次购买事件的占 49.60%；只有一个购买日的则有 393,692 人，占 **77.05%**。140,249 人虽然有至少两条购买记录，却只在一个购买日出现。
- 多购买日用户中，原 `span/(事件数−1)` 的间隔中位数约 11.02 天；用不同购买日数作分母的代理为 22.03 天，二者比值中位数为 2。购物篮中的多件商品容易被当成多次复购，建议新增独立购买日节律，而非仅替换一个缺失值。

不同时间戳和购买日都只是行为聚合代理，数据没有在此提供真实订单关联，不能称为准确订单数。官方 `active_clients.npy` 有 744,980 个编号，与相关用户的交集为 510,971，恰好等于上述历史买家；该文件只用于本次诊断口径核对，不参与表征构建。

全量历史事件中 page_visit 占 88.84%。在旧完整 32 步序列中，非填充事件的 page_visit 占 81.06%；33.61% 用户填满 32 步。历史买家中，15.82% 的最近 32 步没有购买，9.42% 没有购买或加购。伪输入窗口相应比例为 14.92% 与 9.08%。这些数字支持尝试保留购买/加购通道，尚不能证明每个被截断的事件都有预测价值。

## 本地评测的预测间隔

只读 Parquet footer 的时间统计即可确认下列范围；所有行组都有时间戳最小/最大值，无须读取目标事件。输入最后一次事件为 `2022-11-09 23:59:59`。

| 本地目标文件 | 实际最早事件 | 实际最晚事件 | 相对输入截止日 |
| --- | --- | --- | --- |
| train_target | 2022-11-10 00:00:25 | 2022-11-23 23:59:00 | 第 1–14 天 |
| validation_target | 2022-11-24 00:00:20 | 2022-12-07 23:58:25 | 第 15–28 天 |

固定官方提交 `e91c1a6` 的 `training_pipeline/data_module.py:49–60` 向训练集与验证集传入同一个 `self.embeddings` 和 `self.client_ids`，只更换目标 DataFrame；`dataset.py:38–43` 按相同索引返回相同用户的表征。churn 的活跃用户筛选也在两者构造之前统一完成。因此这是同一批用户、同一份截至 11 月 9 日的 X 对两个未来窗口的预测，验证前没有利用 11 月 10–23 日的事件更新 X；它不是用户留出划分。

这意味着只训练“紧接输入的未来 14 天”伪任务，或过度依赖最近几日的购物车余额代理，未必同样适用于第 15–28 天。预测间隔的差异是已确认事实，但它造成多少分差、延迟监督是否有益，都尚未证实。可从历史 input 内另构延迟伪窗口检验；当前购物车特征始终只来自历史输入，不能称为使用了未来加购。

以上仅适用于当前固定官方代码下的**本地模拟评测**。官方 README 的 Data Splitting 说明实际比赛训练/验证目标对参赛者隐藏，本次没有核验线上隐藏目标日期。原始 Parquet 为不含时区信息的 `timestamp[ns]`；上述日期保留其记录值，代码将其解释为 UTC 是本项目的实现约定，不能由文件 schema 反推数据源时区。

## 本轮优先级与维数预算

先以分离行为、短期余额代理、活跃度速度比、精确 URL 和独立购买日节律改善可辨别信息，并用相同特征做缩放对照；再检验多窗口预训练及序列覆盖改进。新方案的目标仍须由固定官方下游评测验收，内部伪任务分数不能代替正式成绩。

已实现的历史特征为 `96+15+4+768+128+64+128=1203` 维，依次为旧统计、速度比、购买日节律、三个行为块各 128 SKU/128 category、URL、PQ、图。默认多窗口预训练输出 `128+64+201=393` 维，拼接后为 `393+1203=1596` 维；本轮正式候选启用延迟预测头，输出 `128+64+201+201=594` 维，拼接后为 `594+1203=1797` 维，两种路径均满足官方 2048 维上限。

延迟路径复用较早窗口 A 的输入、序列与买家掩码，配较晚窗口 B 的目标，由独立的 201 维 delayed 头预测；A/B 各自紧接输入的目标共用另一组 201 维 immediate 头。设计依据是上述本地评测以同一份 X 预测两个不同未来窗口，所有伪目标仍仅由历史 input 构造。两种路径均保留；本轮先比较 594 维预训练组合与不含预训练的 1203 维历史表征，没有单独消融延迟头，不能将整体变化归因于它。393 维默认路径通过合成数据检查，不列为已经完成的百万用户正式实验。意见中的 1200–1500 并不是官方约束；同时堆叠 Top-256、多窗口、多行为块则可能超过上限，必须明确计算，不能机械照搬全部条目。

KKBox 保留已经验证的默认基础入口与明确的最佳配置入口：直接替换所有默认值会改变旧实验语义，清晰的一键最佳配置更合适。行序目标编码的首块没有历史标签，平滑系数从 20 改成 50 后仍只能得到原先验 0.5；随机折外编码会利用后续训练标签，不能再称严格前序编码。是否改用该策略必须另做时间边界明确的实验。根据行号索引取特征不要求输入批次严格单调；额外单调检查反而会拒绝合法乱序批次。多种子或 CatBoost 融合也没有固定的必然涨点幅度。

附件中的 `*_2.py`、`*_3.py` 不是当前仓库正式文件名；源码已使用 `features.py`、`train.py` 等名称，拓展代码也已在此前提交中发布。没有证据支持为这些不存在的版本文件进行清理。

详细数字、原日志 SHA-256 与可重算诊断保存在本地准备资料的 `意见诊断.json`、`预训练诊断.json`、`行为诊断.json`、`类别覆盖诊断.json`、`商品历史覆盖诊断.json`、`分组缩放核验.json`、`评测窗口诊断.json`。仓库仅保存汇总，不上传用户编号或事件明细。
